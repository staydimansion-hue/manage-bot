# 마케팅 PM 봇 기획서

## 1. 목적
- 스테이디멘션 마케팅 팀의 **액션 아이템(A/I)** 을 Slack 채널(`스테이디멘션-마케팅방`)에
  하루 두 번 자동 공유하여 할 일/진행 현황을 한눈에 보게 한다.
- Slack 메시지는 **읽기 전용 현황판**이며, 상태 변경은 **관리자 페이지(`/admin/marketing`)에서만** 한다.
- 채널 대화에서 **구체적 액션 아이템을 자동 추출**(저비용 LLM)하여 등록 누락을 줄인다.
- 추후 운영/살림 봇 등 **두 번째 보드**를 같은 구조(공유 테이블 + `board` 키)로 확장 가능하게 한다.
  (지금은 마케팅 보드만 구현)

## 2. 데이터 모델 (Supabase / Postgres)
- `boards`: 보드 1행(key='marketing', name='스테이디멘션-마케팅방', slack_channel_id, active).
- `categories`: 보드별 카테고리. 마케팅 시드 = 콘텐츠, 광고, SNS, 제휴, 성과분석 (sort_order 1~5).
- `action_items`: 액션 아이템.
  - `status` enum(not_started/in_progress/done, 기본 not_started)
  - `source` enum(manual/auto, 기본 manual)
  - `approved`(기본 true, 자동추출은 false), `due_date`, `created_at`,
    `completed_at`, `archived_at`, `carried_over_count`.
- `extraction_state`: 마지막 처리한 Slack 메시지 ts(새 메시지만 읽기 위함).
- `settings`: 발송 토글 + 같은 날 중복 발송 방지용 `last_morning_sent_on`/`last_evening_sent_on`.

자세한 DDL은 `supabase/schema.sql`, 시드는 `supabase/seed_marketing.sql`.

## 3. 발송 규칙
- 시간대 기준은 **KST(UTC+9)** 의 "하루".
- 오전(09:00 KST) `GET /api/cron/marketing-morning`
  1. 자동추출 → 2. 일일 리셋(롤오버) → 3. "오늘 할 일 + 어제 넘어온 미완료 A/I" 발송 →
     `last_morning_sent_on` 기록.
- 저녁(21:00 KST) `GET /api/cron/marketing-evening`
  1. 자동추출 → 2. "완료·진행중·미완료 마감 리캡" 발송(롤오버 없음) →
     `last_evening_sent_on` 기록.
- 두 엔드포인트 모두 `?token=CRON_SECRET` 필요(없으면 401), 같은 날 재호출은 no-op(`already_sent`).
- 메시지는 Block Kit, 카테고리별 그룹(카테고리 사이에 divider로 구분), 각 항목 접두어
  🟥(완료)/🟨(진행중)/⬜(미진행), 상단 요약 `완료 N · 진행중 N · 미진행 N`, 마감 지난 미완료는 ⚠️.
- 메시지는 **읽기 전용**이며 버튼이 없다. 상태 변경은 관리자 페이지에서만 한다.

## 4. 리셋(롤오버) 규칙
- 보드에 보이는 항목 = **활성 항목**: `approved = true` AND `archived_at IS NULL`.
- 오전 실행 시 롤오버:
  - `status='done'` 이고 `completed_at` 이 **이전 날짜**인 항목 → `archived_at` 설정(보드에서 제외, 이력 보존).
  - 미완료(not_started/in_progress) 항목 → 활성 유지 + `carried_over_count` +1.
- **멱등성**: 이미 archived 된 항목은 다시 처리되지 않으며, 오전 발송 dedupe(`last_morning_sent_on`)로
  같은 날 중복 롤오버를 방지한다.

## 5. 자동추출 (저비용 LLM)
- `extraction_state.last_slack_ts` 이후의 **새 메시지만** `conversations.history` 로 읽음(배치 상한 30, 텍스트만).
- `@anthropic-ai/sdk`, 모델 `ANTHROPIC_MODEL`(기본 `claude-haiku-4-5-20251001`), `max_tokens` 소량.
- 프롬프트: 구체적 마케팅 액션만 `{title, category}` JSON 배열로 추출(카테고리는 5개 중 하나 또는 null).
- 결과는 `source='auto'`, `approved=false`(관리자 승인 대기)로 저장, `last_slack_ts` 갱신.
- API 키 없음/새 메시지 없음/오류 시 **크론을 실패시키지 않고 건너뜀**.

## 6. 관리자 (`/admin/marketing`)
- 서버 렌더링 페이지(모바일/데스크톱). 카테고리 추가/수정/삭제, 액션 아이템 추가/수정/삭제,
  3단계 상태 변경, 자동추출 대기 항목 승인/거절.
- **경량 인증**: 공유 토큰 `?token=ADMIN_TOKEN`. 보안 강화가 필요하면 플랫폼 인증/VPN을 앞단에 둔다.

## 7. 배포 체크리스트
- [ ] `supabase/schema.sql` → `supabase/seed_marketing.sql` 순서로 1회 실행.
- [ ] 환경변수 설정: SLACK_BOT_TOKEN, SUPABASE_URL,
      SUPABASE_SERVICE_ROLE_KEY, ANTHROPIC_API_KEY, ANTHROPIC_MODEL, CRON_SECRET, ADMIN_TOKEN.
- [ ] Slack 앱 생성: scope(chat:write, channels:history/groups:history), 봇을
      `스테이디멘션-마케팅방` 에 초대. (읽기 전용이므로 Interactivity는 꺼도 된다.)
- [ ] `boards.slack_channel_id` 에 실제 채널 ID 반영. **[미정: 실제 channel ID]**
- [ ] cron-job.org에 2개 등록: 오전 09:00 KST, 저녁 21:00 KST, 각각 `?token=CRON_SECRET`.
      **[미정: 발송 시각 미세조정]**
- [ ] 앱 배포(예: Vercel) 후 cron URL이 공개 접근 가능한지 확인.

## 8. 향후 확장
- 두 번째 보드(운영/살림): `boards` 에 새 key 추가, 카테고리 시드, 새 크론 라우트에서
  `runMorning('operations')`/`runEvening('operations')` 호출, 관리자 컴포넌트 재사용.
